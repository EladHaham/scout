# Scout

Scout is a model-agnostic code context engine. Instead of dumping full files into an LLM prompt, Scout builds a small, precise context packet — so the model gets only what it needs.

## How it works

1. **Repo map** — a concise structural overview of the codebase, via Aider's Python API
2. **Symbol notes** — one-sentence descriptions per function/class/interface/type generated by OpenAI (`gpt-4o-mini` by default), cached by structural hash so only changed signatures are re-noted
3. **Call graph** — static AST-based index of caller/callee relationships (Python only), used to expand context to neighbors at retrieval time
4. **Retrieval** — embedding-based search (OpenAI `text-embedding-3-small`) with confidence-aware fallback: tight symbol matches → broader neighbor expansion → whole files → repo map only

## Supported languages

- **Python** — full AST parsing (functions, classes, methods)
- **TypeScript / JavaScript** — via tree-sitter (functions, classes, methods, interfaces, type aliases, namespaces); covers `.ts`, `.tsx`, `.js`, `.jsx`, `.mjs`
- **JSON** — config files indexed as whole-file symbols
- **TOML** — config files indexed as whole-file symbols

Tree-sitter is required only for TS/JS support. If `tree_sitter_typescript` and `tree_sitter_javascript` aren't installed, those files are silently skipped.

## Install

### Option A — Scout app (recommended, macOS Apple Silicon)

The Scout app handles the venv setup, the `scout-mcp` install, and wires Scout into Claude Desktop automatically.

1. Download the latest `Scout-<version>-arm64.dmg` from [Releases](https://github.com/EladHaham/scout/releases/latest).
2. Open the `.dmg` and drag Scout to Applications.
3. **First launch**: macOS will block the unsigned app. Right-click Scout in Applications → **Open** → **Open**. You only need to do this once.
4. Add your OpenAI key to `<repo>/.env`:
   ```
   OPENAI_API_KEY=sk-...
   ```
5. In Scout, click **Add repository** and pick your git repo. Scout will set up the venv, install `scout-mcp`, and add itself to Claude Desktop's MCP config.
6. **Restart Claude Desktop** when prompted (Cmd+Q, then relaunch).
7. In a new Claude chat, click the tools icon. You should see `scout_notes`, `scout_context`, `scout_index_status`, `scout_read_file`.

### Option B — Manual install

If you want to use Scout with a non-Claude MCP client (Cursor, etc.) or prefer to set things up yourself:

**Requirements**

- Python 3.12 specifically
- `git`
- An OpenAI API key

```bash
git clone https://github.com/EladHaham/scout.git
cd scout

python3.12 -m venv .venv
source .venv/bin/activate
pip install -e .
pip install aider-chat

# Optional, for TS/JS support:
pip install tree-sitter tree-sitter-typescript tree-sitter-javascript

# Verify install
python -c "from scout.mcp.server import main; print('ok')"
```

Add your key to `.env`:

```
OPENAI_API_KEY=sk-...
```

Add to your Claude Desktop config at `~/Library/Application Support/Claude/claude_desktop_config.json`:

```json
"mcpServers": {
  "scout": {
    "command": "/absolute/path/to/your/.venv/bin/scout-mcp",
    "args": ["/absolute/path/to/your/repo"],
    "env": { "OPENAI_API_KEY": "sk-..." }
  }
}
```

**Fully quit Claude Desktop** (Cmd+Q — closing the window is not enough) and relaunch.

## CLI

The same engine is usable from the command line, no MCP client required:

```bash
scout notes .                              # index repo (run once, then on changes)
scout context . "how is caching done"      # retrieve context for a task
scout map .                                # repo map only
scout init .                               # write .scout/config.json for tuning
```

## Caching

- **Repo map** — `~/.scout/cache/`, invalidated on git HEAD or working tree changes
- **Symbol notes** — `.scout/notes/`, invalidated per-symbol when name or signature changes
- **Embeddings** — `.scout/embeddings.<model>.json`, content-hash keyed and namespaced per embedding model (switching models doesn't return stale vectors)
- **Call graph** — `.scout/call_graph.json`, rebuilt on every `scout notes` run
- **Index fingerprint** — `.scout/index_fingerprint.json`, last successfully-indexed git fingerprint (used by the MCP server to decide whether to auto-reindex)
- **Event log** — `.scout/scout.log`, NDJSON append-only log of every retrieval and indexing run

Add `.scout/` to your `.gitignore`.

## Known limitations

- **Module-level constants are not indexed.** The parser only emits symbols for functions, classes, methods, interfaces, type aliases, and config files. Queries that name a constant directly (e.g. `MIN_DIRTY_FOR_API`) will return unrelated nearby symbols rather than failing visibly — the dashboard shows a low score, not a missing entry. Workaround: query for the function that uses the constant.
- **Call graph is Python-only.** TS/JS symbols are parsed and get notes/embeddings, but their caller/callee edges are not tracked. Neighbor expansion (tier 2 retrieval) does nothing useful on TS-heavy repos — you get direct embedding hits only.
- **Dynamic dispatch, polymorphism through abstract interfaces, and reflective calls** are not resolved in the call graph. This includes Scout's own port/adapter pattern — calls through `RepoMapper` or `NoteGenerator` interfaces are invisible to static analysis.
- **Static-analysis only** — runtime call relationships (e.g. event handlers, decorators that wrap callables, `getattr(obj, name)()`) may not appear.
- **Top-level TypeScript symbols collide across files.** Two files each with a top-level `function foo()` produce two symbols both named `foo`. The note store keys by `file:symbol` to disambiguate but the call graph and retrieval index don't currently file-scope TS names.

## Project structure

```
scout/                  # Python package (MCP server + CLI)
  cli.py                # CLI entry point
  service.py            # Repo map orchestration
  config.py             # ScoutConfig + per-repo .scout/config.json
  adapters/
    aider_mapper.py     # Aider Python API wrapper
    filesystem.py       # Git root detection, repo fingerprinting
  domain/
    models.py           # RepoMapResult, SymbolNote dataclasses
    ports.py            # RepoMapper, NoteGenerator abstract interfaces
  notes/
    parser.py           # Language dispatcher
    parsers/
      base.py           # Shared ParsedSymbol, structural_hash, is_test_file
      python.py         # Python AST parser
      typescript.py     # TS/JS/JSX/TSX tree-sitter parser
      json.py           # JSON config indexer
      toml.py           # TOML config indexer
    generator.py        # OpenAI-backed note generator
    store.py            # Note persistence (per-symbol JSON)
    service.py          # Note generation orchestration (with orphan pruning)
    call_graph.py       # Static call graph builder
  retrieval/
    embedder.py         # OpenAI embedding with content-hash cache
    index.py            # Flat cosine similarity vector index
    service.py          # Context assembly with confidence-aware fallback
  storage/
    cache.py            # Repo map cache (keyed by git fingerprint)
  mcp/
    server.py           # MCP server (FastMCP), background indexing, staleness detection
  utils/
    errors.py
    logger.py           # NDJSON event log

scout-app/              # Electron desktop app (macOS)
```
